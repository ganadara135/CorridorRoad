# V1 Applied Section Supplemental Sampling Redesign Plan

Status: Draft

Scope: move supplemental sampling ownership from Build Corridor to Applied Sections so downstream surfaces consume complete evaluated section results, not output-only frame markers.

Supersedes:

- [V1_SUPPLEMENTAL_FRAME_SAMPLING_PLAN.md](./V1_SUPPLEMENTAL_FRAME_SAMPLING_PLAN.md)

## Purpose

Curved 3D Centerline output should be followed by complete `AppliedSection` results.

The current supplemental frame behavior can create extra placement frames in Build Corridor, but those frames are not first-class Applied Sections.

This causes a mismatch:

- green Applied Sections contain evaluated Assembly/Subassembly point, link, shape, and surface roles
- yellow supplemental frames can exist only as output/build samples
- surfaces need the green-style evaluated section payload, not just a frame glyph

This plan moves supplemental station creation and section evaluation into `Applied Sections`.

Build Corridor should consume the expanded `AppliedSectionSet` and stop inventing hidden section samples.

## Scope

This plan covers:

- terminology change from supplemental frame to supplemental Applied Section
- Applied Sections sampling ownership
- curve detection and station placement rules
- UI relocation from Build Parametric to Applied Sections
- AppliedSectionSet schema and diagnostics expectations
- Build Parametric consumption changes
- migration from the existing Build Corridor supplemental frame implementation
- validation and manual QA criteria

This plan does not make supplemental sections editable source rows.

## Core Rule

`Centerline3DResult` owns the baseline station, offset, elevation, and tangent frame.

`Applied Sections` owns station-wise section evaluation.

Therefore, supplemental curve samples must become result-only `AppliedSection` rows inside `AppliedSectionSet`.

`Build Parametric` must consume those rows.

It must not generate hidden supplemental section geometry after Applied Sections has already produced the accepted section result set.

## Design Goals

- Make corridor surfaces follow the reviewed 3D Centerline curve.
- Ensure every surface frame has evaluated Assembly/Subassembly geometry.
- Keep user station rows stable and readable.
- Make supplemental density a section-generation option, not a surface-generation option.
- Preserve source traceability for lane, shoulder, ditch, side slope, drainage, and slope face rows.
- Let users review supplemental section count before building corridor surfaces.
- Avoid duplicate sampling logic between Applied Sections and Build Parametric.
- Keep performance predictable with caps and diagnostics.

## Terminology

| Term | Meaning |
| --- | --- |
| Source station | A station authored by Stations, Region boundaries, Intersections, Structures, Drainage, or explicit user input. |
| Applied Section | A complete station-specific result containing frame, Subassembly rows, points, links, shapes, diagnostics, and source refs. |
| Supplemental station | A result-only station inserted by Applied Sections between source stations to improve downstream geometry continuity. |
| Supplemental Applied Section | A complete `AppliedSection` built at a supplemental station. |
| Section series | The ordered `AppliedSectionSet.sections` list containing source and supplemental Applied Sections. |
| Build frame | A downstream placement frame read from an Applied Section. It is not independently generated by Build Parametric. |
| Chord | The straight line between two evaluated points on a curve. |
| Chord deviation | The distance between the true evaluated curve point and the straight chord between the span endpoints. |
| Horizontal chord deviation | Chord deviation measured in plan XY. |
| Vertical chord deviation | Chord deviation measured in elevation Z against the straight endpoint grade line. |
| 3D chord deviation | Chord deviation measured in XYZ space. |
| Grade delta | Change in profile grade between two evaluated stations. |

Avoid user-facing wording that suggests supplemental samples are only frames.

Use `Supplemental Sections` where possible.

## Ownership Model

| Stage | Owns | Does not own |
| --- | --- | --- |
| `3D Centerline` | shared station/frame lookup baseline | section shape, Subassembly geometry, surfaces |
| `Applied Sections` | source stations, supplemental stations, evaluated section result rows | final corridor surfaces and solids |
| `Build Parametric` | surfaces, review objects, corridor-derived outputs from Applied Sections | supplemental station generation, Subassembly expression evaluation |

## User Workflow

1. User builds or reviews `3D Centerline`.
2. User opens `Applied Sections`.
3. User enables `Supplemental Sections`.
4. User chooses curve sampling density and advanced thresholds.
5. User clicks `Apply`.
6. Applied Sections creates source and supplemental Applied Sections.
7. Applied Sections summary reports source count, supplemental count, total count, trigger counts, and fallback count.
8. User optionally previews supplemental section markers.
9. User opens `Build Parametric`.
10. Build Parametric consumes the expanded AppliedSectionSet.
11. Surface diagnostics report how many source and supplemental Applied Sections were consumed.

## Sampling Inputs

Applied Sections should build supplemental stations from:

- accepted source stations
- Region start and end stations
- Assembly/Subassembly template change stations
- explicit override boundaries
- Intersection supplemental stations
- Structure hard break stations when they alter section shape
- Drainage hard break stations when ditch, gutter, or side-slope behavior changes
- 3D Centerline tangent change
- 3D Centerline chord deviation
- Profile vertical chord deviation
- Profile grade delta
- maximum spacing
- optional profile grade/elevation delta
- optional superelevation crossfall delta

## Placement Rules

Start with required source and hard-break stations.

Hard-break stations are always preserved.

Optional supplemental stations are inserted only between two consecutive stations when one or more enabled rules exceed the user thresholds.

Initial defaults:

| Rule | Default | User control |
| --- | --- | --- |
| Supplemental Sections | on | checkbox |
| Density | medium | slider |
| Maximum spacing | 5 m | derived from density, advanced editable later |
| Maximum tangent change | 3 degrees | Options tab |
| Maximum chord deviation | 0.25 m | Options tab |
| Maximum vertical chord deviation | 0.10 m | Options tab |
| Maximum grade delta | 1.0% | Options tab |
| Maximum supplemental sections per span | 32 | internal cap first, advanced later |

Recommended density mapping:

| Density | Max spacing |
| --- | --- |
| Low | 10 m |
| Medium | 5 m |
| High | 2 m |
| Very High | 1 m |

The sampler may recursively split spans until all active rules pass or the cap is reached.

Curved spans should be detected from `Centerline3DResult` geometry and Profile evaluation, not from straight interpolation between existing Applied Section points.

Horizontal curves and vertical curves must both trigger supplemental sections.

Do not rely only on XY tangent direction.

Strong vertical curves may have little or no horizontal tangent change.

For those spans, Applied Sections must compare the evaluated mid-station elevation against the straight grade chord between the span endpoints.

If the vertical deviation or grade delta exceeds the configured threshold, insert supplemental Applied Sections even when the XY alignment is straight.

## AppliedSectionSet Contract Changes

`AppliedSectionSet.station_rows` should record the station kind clearly.

Recommended kinds:

- `source`
- `region_boundary`
- `intersection_supplemental`
- `structure_break`
- `drainage_break`
- `curve_supplemental`
- `spacing_supplemental`
- `fallback_supplemental`

Each supplemental `AppliedSection` should keep:

- evaluated `frame`
- `frame.notes` containing `source=centerline3d_result` when available
- normal Subassembly rows
- normal point/link/shape rows
- source refs to the Centerline3DResult and owning source models
- diagnostics explaining why the station was inserted

Supplemental Applied Sections must be complete enough that Build Parametric does not need to interpolate Subassembly profiles for ordinary surface generation.

## Centerline Frame Correction Plan

The supplemental section count is not the root issue when Applied Sections are visibly centered on the Profile chord instead of the 3D Centerline.

Supplemental Applied Sections only add more stations.

They cannot fix the result if each station frame is resolved from the wrong baseline.

### Problem

`Centerline3DFrameService.resolve_station()` currently resolves a station by linear interpolation between sparse `Centerline3DResult.point_rows`.

That creates a chord between stored points.

On strong vertical curves, the chord can follow a simplified red Profile line or straight segment instead of the cyan 3D Centerline curve visible in the model.

As a result:

- Applied Section origins can drift away from the actual 3D Centerline.
- Supplemental Applied Sections can become dense but still wrong.
- Corridor surfaces built from those sections inherit the wrong baseline.

### Core Rule

Applied Sections must be centered on the evaluated 3D Centerline frame.

Supplemental sampling controls density only.

Frame evaluation controls correctness.

### Target Behavior

For any station:

1. Resolve the station on the authoritative 3D Centerline path.
2. Return frame origin `x`, `y`, and `z` on that path.
3. Return tangent from the local 3D Centerline direction, not from a long sparse chord.
4. Return grade from Profile or 3D Centerline local derivative consistently.
5. Mark diagnostics when the service must fall back to sparse point interpolation.

### Preferred Implementation Direction

The preferred fix is to make `Centerline3DFrameService` evaluate from source/result context in this order:

1. Use a dense or parametric `Centerline3DResult` station evaluator when available.
2. If only sparse `point_rows` exist, use short-window interpolation around the station rather than long-span chord interpolation.
3. For vertical elevation, evaluate `ProfileModel` at the station when the active Centerline3D result does not provide sufficient local Z samples.
4. Preserve the shared service as the single frame authority for Applied Sections, Build Parametric, preview markers, and surface output.

### Diagnostics

Add diagnostics that are visible in Applied Sections review:

| Diagnostic kind | Severity | Meaning |
| --- | --- | --- |
| `centerline3d_frame_source_evaluated` | info | Frame was resolved from the corrected 3D Centerline evaluator. |
| `centerline3d_frame_sparse_chord_fallback` | warning | Frame used sparse point-row chord interpolation because no better evaluator was available. |
| `centerline3d_frame_profile_delta` | warning | Frame Z differs from Profile evaluation beyond threshold. |
| `applied_section_origin_off_centerline3d` | warning | Applied Section origin appears offset from expected 3D Centerline position. |

### Implementation Order for Frame Correction

1. Inspect the Centerline3D creation path and confirm whether it stores dense curve rows or only sampled point rows.
2. Extend `Centerline3DFrameService` with an explicit evaluated-frame path.
3. Keep sparse point-row interpolation only as a fallback with diagnostics.
4. Route Applied Section build through the corrected service without adding separate geometry logic inside the panel.
5. Update supplemental section diagnostics so dense supplemental rows are described as density, not baseline correction.
6. Add focused FreeCADCmd tests for strong vertical curve station origins.
7. Add manual QA steps comparing red Profile, cyan 3D Centerline, and green Applied Section origins.

## Migration Notes

The existing `V1_SUPPLEMENTAL_FRAME_SAMPLING_PLAN.md` implemented Build Corridor-owned output densification.

That approach is superseded because surface generation needs evaluated Applied Section payloads.

During migration:

- keep existing helper code only if it can be moved behind Applied Sections
- keep marker visualization, but relabel it as supplemental section markers
- preserve user thresholds where possible
- avoid creating both Build Parametric generated frames and Applied Sections supplemental rows at the same time
- remove duplicate interpolation once Applied Sections emits complete rows

## Acceptance Criteria

- Applied Sections on a curved 3D Centerline produce more sections than the source station count when thresholds require it.
- Applied Sections on a strong vertical curve produce supplemental sections even when the horizontal alignment is nearly straight.
- Vertical supplemental sections report `supplemental_section_vertical_curve_trigger`.
- Supplemental Applied Sections contain Subassembly rows, point rows, link rows, shape rows, and frame provenance.
- Build Parametric surface output changes when Applied Sections density changes.
- Build Parametric no longer generates hidden supplemental frames for normal surface generation.
- Lane, shoulder, ditch, and side slope surfaces use the same expanded AppliedSectionSet.
- Build Parametric preview provenance reports consumed supplemental Applied Sections.
- The 3D marker preview lies on the reviewed 3D Centerline curve.
- Applied Section origin markers lie on the cyan 3D Centerline through strong vertical curves.
- Increasing supplemental section density changes smoothness, not baseline location.
- A sparse Centerline3DResult fallback is visible through diagnostics.
- Fallback to non-centerline frame sources is visible as a warning.
- User source stations do not change when density changes.

## Manual QA Checklist

- Build a sparse station project with a visibly curved 3D Centerline.
- Build a sparse station project with a strong sag or crest vertical curve and little horizontal curvature.
- Run Applied Sections with Supplemental Sections off.
- Confirm source and total section counts match.
- Run Applied Sections with Supplemental Sections on at Low density.
- Confirm supplemental section count is greater than zero on the curve.
- Confirm supplemental section count is greater than zero on the strong vertical curve.
- Run Applied Sections at Very High density.
- Confirm supplemental section count increases.
- Build Parametric after each Applied Sections run.
- Confirm the surface follows the 3D Centerline more closely at higher density.
- Confirm Build Parametric preview provenance reports consumed supplemental Applied Sections, not generated supplemental frames.
- Confirm ditch, side slope, shoulder, and lane highlights continue through supplemental sections.
- Confirm changing density does not add source station rows.
- In a strong vertical curve case, compare the red Profile line, cyan 3D Centerline, and green Applied Section origins.
- Confirm Applied Section origins follow the cyan 3D Centerline, not the red Profile chord.
- Confirm warnings appear when a sparse Centerline3DResult fallback is used.

## Risks

| Risk | Mitigation |
| --- | --- |
| Applied Sections runtime increases. | Add density caps, summary counts, and performance diagnostics. |
| Users may confuse supplemental sections with editable station rows. | Label them result-only and keep source station table unchanged. |
| Multiple source changes create duplicate supplemental stations. | Normalize station keys and preserve trigger lists per station. |
| Build Parametric and Applied Sections both densify during migration. | Add a clear feature gate and diagnostic confirming hidden Build Parametric sampling is disabled. |
| Dense supplemental sections still follow the wrong baseline. | Correct `Centerline3DFrameService` before treating supplemental density as a surface fix. |
| Frame correction logic is duplicated in panels or Build Parametric. | Keep `Centerline3DFrameService` as the shared frame authority. |
| Existing docs describe the old behavior. | Mark the old plan as superseded and update wiki pages. |

## Non-goals

- Do not make supplemental sections editable source rows.
- Do not make Applied Sections build final corridor surfaces.
- Do not replace Centerline3DResult ownership.
- Do not hide fallback frame sources.
- Do not use Build Parametric as the primary supplemental station owner after migration.
- Do not use supplemental section density to mask incorrect 3D Centerline frame placement.
